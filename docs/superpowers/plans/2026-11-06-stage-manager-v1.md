# StageManager4win v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the deleted demo with a Windows 11 Stage Manager clone: one independent stage per monitor, a strip of live window previews, fast switching, and a WinForms shell.

**Architecture:** A pure `StageManager4win.Core` library owns window grouping, MRU ordering, stage/strip transitions, layout math, and settings. `StageManager4win.App` is a WinForms tray application that enumerates windows, watches WinEvents, creates one `WS_EX_NOREDIRECTIONBITMAP` overlay HWND per monitor, and renders tiles through D3D11 + DirectComposition. Windows Graphics Capture supplies live frames; icons are the fallback. A render thread owns the D3D11/DComp device, capture sessions, and tile surfaces. The UI thread owns the model, hooks, hotkeys, and UIA.

**Tech Stack:** .NET 10, C# 14, WinForms shell, CsWin32 0.3.367, D3D11, DirectComposition, Windows Graphics Capture, DirectWrite-free UI, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-06-stage-manager-rewrite-design.md`

## Global Constraints

- Windows 11 22H2+ (build 22621). TFM `net10.0-windows10.0.22621.0`; `SupportedOSPlatformVersion` `10.0.22621.0`.
- Win32 interop comes from CsWin32 `0.3.367`. No Vortice, Win2D, or WinUI. Hand-write only a missing `[ComImport]` method or interface.
- WinForms is the shell. The overlay is a top-level HWND with a DirectComposition target, not a WinForms control.
- One tile per window. App grouping (one tile per app) is out of scope for v1 and no dead "group by app" setting may appear.
- Each monitor has its own stage, strip, and active app. A window belongs to exactly one monitor: the monitor containing the window centre.
- Never move or resize another app's window. Activation only restores/raises it.
- Per-monitor DPI awareness v2. Layout is in DIPs; surfaces and window regions are in physical pixels.
- `WS_EX_NOREDIRECTIONBITMAP` overlay, no `WS_EX_LAYERED`. `WM_MOUSEACTIVATE` returns `MA_NOACTIVATE`.
- Strip defaults: left edge, width 12% of monitor width clamped to 160–320 DIP, 30 DIP gap, 160×120 DIP maximum tile box, vertical centering in the work area.
- Preview frame rate defaults to 30 fps; allowed values 15/30/60.
- Settings live in `%LOCALAPPDATA%\StageManager4win\settings.json`; workspace order lives in `workspace.json` in the same directory. Both are written atomically.
- Default hotkeys: `Ctrl+Alt+Space` toggle, `Ctrl+Alt+Period` next, `Ctrl+Alt+Comma` previous, `Ctrl+Alt+D` show desktop. All configurable.
- Accessibility: every tile is a UIA Button named `App — Title` with `InvokePattern`; the hidden strip keeps its UIA tree alive.
- The product must never leave a window hidden, minimized, or unclickable. Every state change has a recovery path.
- Capture is best-effort: HDR, DRM, elevated, or failed captures fall back to an icon tile.
- Do not log full window titles by default.

## Review Focus

1. **Click-through and focus:** a click on an empty area between tiles must reach the window underneath, and a click on a tile must not activate the overlay or steal focus.
2. **200% DPI:** tile visuals, window regions, hover hit-testing, and the settings window must line up; surfaces must not be drawn at double or half size.
3. **Monitor hotplug:** unplugging the monitor that owns the foreground window while its tile is hovered must not leave a stale overlay, a stale capture, or a crash.
4. **Capture lifetime:** closing or minimizing a captured window while a frame is pending must not use a freed surface, crash, or leave a permanently black tile.
5. **Activation refusal:** an elevated window or a foreground lock that refuses `SetForegroundWindow` must not desync the model; the tile must remain and the user must get feedback.

Each line above is pinned by a test or a manual check in the task that owns the code.

Tasks 3–8 and the build steps in Task 1 run on any OS with the .NET 10 SDK. Tasks 2 and 9–20 require a Windows 11 22H2+ machine for their verification steps. Do not mark a Windows-only task complete from a macOS build alone.

  - `StageModel` keeps list order: index 0 is the most recent.

**Rules for this task:**
- `Reset` clears all state, registers every window, and groups by `MonitorId`.
- With no foreground, each monitor's `Strip` is the windows in input order and `Stage` is empty.
- With a foreground, apply the foreground rule after registration.
- `SetForeground(w)`: if unknown, return false. Otherwise `M = monitor(w)`, `M.Stage = [w]`, remove `w` from `M.Strip`, prepend every previous stage window that is not in the new stage to `M.Strip` in its previous stage order, set `M.Foreground = w`, `M.ActiveAppId = w.AppId`. Other monitors are unchanged.
- Re-foregrounding the current window is a no-op that returns true.

### Task 5: Stage model modes and window lifecycle

**Files:**
- Modify: `src/StageManager4win.Core/Stages/StageModel.cs`
- Test: `tests/StageManager4win.Core.Tests/StageModelTests.cs`

**Interfaces:**
- Consumes: Task 4's `StageModel`.
- Produces: additional members on `StageModel`:
  - `void Add(WindowSnapshot window)`
  - `void Update(WindowSnapshot window)`
  - `void Remove(WindowId window)`
  - `void Minimize(WindowId window)`
  - `void Restore(WindowId window)`
  - `bool Activate(WindowId window)` (same model transition as `SetForeground`)
  - `SetMode` now re-evaluates every monitor that has a foreground.

**Rules:**
- `AllAtOnce`: stage = `[foreground] + other windows of the same app on that monitor that are visible and not minimized`, ordered by current stage order then current strip order. `Automatic` behaves as `OneAtATime`.
- New window: if `AllAtOnce` and its app is the monitor's `ActiveAppId` and it is visible and not minimized, insert at the top of the stage; otherwise insert at the top of the strip.
- Minimize: mark minimized. If it was on stage, remove it, insert at the top of the strip, and clear `Foreground` if it was foreground. If it was in the strip, keep its position. Leave `ActiveAppId` alone.
- Restore: clear the minimized flag; do not move the window. The foreground event that follows performs the stage transition.
- Remove: delete the window from metadata and both lists. Clear `Foreground` if it matched. Clear `ActiveAppId` when the app has no windows left on that monitor. Remove an empty monitor state.
- Update with a different monitor: remove from the old monitor; if it was the old foreground, set the old `Foreground` to null; if the old stage is now empty and the old strip is non-empty, promote the strip's first window to the stage and set `ActiveAppId` to its app; if the old `ActiveAppId` has no windows left on the old monitor, clear it. Insert the window at the top of the new monitor's strip; the foreground event that follows moves it to the stage.
- `SetMode`: store the mode, then for every monitor with a known foreground re-apply the foreground rule.

**Interfaces:**
- Consumes: `WindowId`.
- Produces:
  - `readonly record struct RectD(double X, double Y, double Width, double Height)`
  - `enum StripEdge { Left, Right }`
  - `readonly record struct StripItem(WindowId Window, double AspectRatio)`
  - `sealed record StripLayoutOptions(double MonitorWidth, double MonitorHeight, double WorkAreaTop, double WorkAreaHeight, StripEdge Edge = StripEdge.Left, double MaxTileWidth = 160, double MaxTileHeight = 120, double Gap = 30, double StripWidthRatio = 0.12, double MinStripWidth = 160, double MaxStripWidth = 320)`
  - `readonly record struct TilePlacement(WindowId Window, RectD Bounds)`
  - `sealed record StripLayout(IReadOnlyList<TilePlacement> Tiles, int FirstVisibleIndex, int VisibleCount)`
  - `static StripLayout StripLayoutCalculator.Calculate(IReadOnlyList<StripItem> items, StripLayoutOptions options, int firstVisibleIndex = 0)`

**Rules:**
- `WorkAreaTop` and `WorkAreaHeight` are monitor-local DIPs.
- Strip width = `Clamp(MonitorWidth * StripWidthRatio, MinStripWidth, MaxStripWidth)`.
- Aspect ratio = `Clamp(item.AspectRatio, 0.25, 4.0)`; NaN or infinity becomes 1.333.
- Tile fits inside `MaxTileWidth × MaxTileHeight`: `width = Min(MaxTileWidth, MaxTileHeight * aspect)`, `height = width / aspect`.
- `firstVisibleIndex` is clamped to `0..items.Count`.
- From that index, include items while `totalHeight + Gap + nextHeight <= WorkAreaHeight`; always include the first item if one exists.
- The visible stack is centered vertically in the work area.
- Left edge: `x = (stripWidth - tileWidth) / 2`. Right edge: `x = MonitorWidth - stripWidth + (stripWidth - tileWidth) / 2`.
- `VisibleCount` is the number of rendered tiles.

**Coordinator rules:**

- `Reconcile`: enumerate snapshots. For known ids not present, `model.Remove`. For new ids, `model.Add`. For existing ids, `model.Update`. Then if the foreground hwnd maps to a known window and differs from the model's foreground, call `model.SetForeground`. Then `Refresh()`.
- `DesktopSwitch`: dispose captures? For now call `Rebuild()` after 100 ms: `model.Reset(snapshots, foreground)`.
- `Refresh`:
  - For each monitor, get `MonitorState`.
  - Build `StripItem` list from `state.Strip`, using `bounds.Width / bounds.Height` clamped by the layout.
  - Apply `MaxVisibleStripItems` and the per-monitor `_firstVisibleIndex`.
  - Convert the monitor's physical bounds to DIPs: `dip = px * 96.0 / dpi`.
  - `StripLayoutCalculator.Calculate`.
  - Build `TileVisual` list; icon = cached icon for `AppId` (load from `ExecutablePath`), or solid fallback; minimized flag from the snapshot.
  - `overlay.SetTiles(tiles)`, `overlay.SetVisible(_visibleByMonitor.TryGetValue(monitor, out var visible) ? visible : true)`, `renderThread.Post(new UpdateOverlay(...))`.
  - Send `CreateOverlay` once per monitor at startup and after display changes.
- `ActivateWindow(id)`: `model.Activate(id)`; if `Mode == AllAtOnce`, restore every window in that monitor's new `Stage`, then activate the clicked window; `Refresh()`. If activation returns false, call `Reconcile()` to resync and raise `StatusMessage("Windows refused to activate the window.")`.
- `ToggleStripUnderPointer`: monitor under `Cursor.Position` (fallback foreground monitor); flip its visible flag; `Refresh()`.
- `Cycle(delta)`: take the monitor under the pointer (fallback foreground monitor). Create a `CycleCursor` from that monitor's full strip on the first call; keep it in `_cycle`; advance by delta with `isEligible = id => model.Windows.ContainsKey(id)`; activate the result. Reset `_cycle` after 2 seconds with a WinForms timer.
- `ShowDesktop`: `Type.GetTypeFromProgID("Shell.Application")`, `Activator.CreateInstance`, invoke `ToggleDesktop` via reflection; catch and raise `StatusMessage`.
- Scroll: on `ScrollRequested`, adjust `_firstVisibleIndex` for that monitor by `Math.Sign(delta)` and clamp to `0..max(0, stripCount - 1)`; `Refresh()`.

- Never call `SetWindowPos` to move the target window.
